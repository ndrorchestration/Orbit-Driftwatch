# Orbit Driftwatch

**Observable Multi-Agent Reasoning**

Orbit Driftwatch is a public showcase application for making multi-agent workflow behavior visible and understandable. It combines **Driftwatch-derived observability**—roles, traces, disagreement, evidence coverage, source bindings, and failure visibility—with **Orbit-derived interpretation** through plain-language Today, Patterns, and Open Questions views.

> **Current status: PROVIDER + RETRIEVAL ARCHITECTURE IMPLEMENTED / DETERMINISTIC CONTROL VERIFIED.** The deterministic provider remains the reproducible default. A server-backed OpenAI Responses provider, built-in web-search retrieval path, and source-provenance contract are implemented and CI-tested. Live hosted execution/retrieval is **not yet verified** because it requires an authorized server deployment with a server-only `OPENAI_API_KEY`. Internal telemetry is not a measure of factual correctness.

## Claim-to-evidence audit demonstration

`claim-audit.html` is a separate deterministic portfolio surface for a narrower governance question: **does the declared evidence actually support a readiness claim?**

The default scenario evaluates the claim **“This system is ready for a pilot.”** It deliberately starts with automated software checks and artifact provenance marked `VERIFIED`, while independent review is `NOT EXECUTED`, freeze is `NOT ESTABLISHED`, and pilot authorization is `NOT GRANTED`. The evaluator therefore fails closed instead of converting engineering success into permission to proceed.

The demonstration:

- separates engineering, provenance, governance, authorization, and empirical evidence classes;
- recomputes the strongest supported claim as gate states change;
- identifies the next unresolved required gate;
- keeps empirical efficacy separate from the prerequisites for beginning a properly authorized pilot;
- exports a portable JSON audit record; and
- runs without a model or external service so the decision logic is directly inspectable and reproducible.

This demonstration evaluates **declared procedural evidence only**. It does not establish factual correctness, scientific efficacy, security, production reliability, or the validity of any external evidence source.

## Implemented and tested

- Deterministic four-role workflow: Planner, Researcher, Skeptic, Verifier.
- Provider-neutral asynchronous execution contract with stable provider identity/version.
- Deterministic offline provider retained as a reproducible control fixture.
- Server-backed OpenAI Responses adapter with a server-only credential boundary.
- Server-side OpenAI built-in web-search retrieval pass.
- Bounded/deduplicated HTTP(S) source records with stable source IDs and retrieval timestamps.
- Explicit claim `sourceRefs` and `conflictingSourceRefs`, with duplicate/orphan rejection.
- Shared fail-closed validation for deterministic and hosted provider output.
- Provider timeout handling and strict size/count/stance/evidence boundaries.
- Negative controls for malformed output, provider outage, source-reference errors, hostile markup, and boundary violations.
- Mechanically defined observability metrics: disagreement, evidence coverage, unsupported claims, convergence complement, and observed role count.
- Orbit interpretation translating telemetry into Today / Patterns / Open Questions.
- JSON run artifacts preserving provider identity and non-empty source provenance.
- Frozen deterministic example with SHA-256 sidecar regenerated byte-for-byte in CI.
- Deterministic claim-readiness evaluator with fail-closed missing-gate behavior and regression tests.
- Browser showcase UI with deterministic and hosted-provider selection; no model credential is accepted by browser code.
- GitHub Pages deployment workflow prepared, but Pages site creation is blocked by repository-administration permission and therefore kept manual to avoid false-red main builds.

## Run locally

The deterministic showcase requires no package dependencies:

```bash
python -m http.server 4173
```

Open `http://localhost:4173` and keep **Deterministic control** selected. The claim-to-evidence demonstration is available at `http://localhost:4173/claim-audit.html`.

Verification:

```bash
npm test
```

### Hosted model + retrieval mode

Hosted mode requires a server runtime capable of serving `api/run-agents.js` and a server-only OpenAI key:

```bash
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.6-luna  # optional override
```

Never place the key in browser code or a public-prefixed environment variable. The server performs a web-search research pass, derives a bounded source catalog from returned source metadata, then performs synthesis against those source IDs. The downstream workflow rejects orphaned source references. This architecture does **not** make retrieval results automatically true; claims still require evaluation against their bound evidence.

## Relationship to other projects

Orbit Driftwatch is an independent integration/showcase application. It adapts patterns from Orbit and Driftwatch, but cross-repository lineage does not transfer validation or evidence. DGAF, Tektite, MORSE, Amethyst, and Agent Control Plane remain separate projects with separate evidence boundaries.

The claim-to-evidence demonstration uses governance concepts that are relevant to those systems, but it does **not** import or upgrade their evidence state. A real DGAF/PDMAL readiness decision must still resolve through that project's own exact-bound governance and evidence records.

## Remaining promotion gates

1. Enable a dedicated public deployment target through an authorized repository/deployment administrator.
2. Configure a server-only `OPENAI_API_KEY` on that target and execute one provider-bound live retrieval run.
3. Verify the deployed run artifact preserves provider identity plus source/claim bindings end to end.
4. Enable repository-enforced required CI for `main` with stale-head protection.
5. Complete accessibility/responsive review and deployment-matched screenshots.
6. Evaluate factual quality externally before interpreting any internal metric as a quality signal.

Tracked gates: issues #4–#7.
