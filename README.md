# Orbit Driftwatch

**Observable Multi-Agent Reasoning**

Orbit Driftwatch is a public showcase application for making multi-agent workflow behavior visible and understandable. It combines **Driftwatch-derived observability** (roles, traces, disagreement, evidence coverage, failure visibility) with **Orbit-derived interpretation** (plain-language Today, Patterns, and Open Questions views).

> **Current status: PROVIDER-READY / DETERMINISTIC CONTROL VERIFIED.** The deterministic provider remains the reproducible default. A server-backed OpenAI Responses provider and source-provenance contract are implemented and CI-tested, but live hosted-model execution is **not yet verified** because it requires a deployed server with `OPENAI_API_KEY`. External retrieval is **not yet implemented**. Internal telemetry is not a measure of factual correctness.

## Architecture

```text
Question
  ↓
Provider boundary
  ├─ deterministic-demo (offline control)
  └─ openai-responses-server (server-backed adapter)
  ↓
Planner → Researcher → Skeptic → Verifier
  ↓             ↓
trace       claims/evidence
                 ↓
       optional source bindings
       sourceRefs / conflictingSourceRefs
  └──────────┬──────────┘
             ↓
         Driftwatch
    observability metrics
             ↓
           Orbit
    plain-language meaning
             ↓
 Explainable run summary + portable artifact
```

## What is implemented

- Deterministic four-role workflow: Planner, Researcher, Skeptic, Verifier.
- Provider-neutral asynchronous execution contract with stable provider identity/version.
- Deterministic offline provider retained as the reproducible control fixture.
- Server-backed OpenAI Responses adapter using a server-only `OPENAI_API_KEY` boundary.
- Shared fail-closed validation for deterministic and hosted provider output.
- Provider timeout handling and strict size/count/stance/evidence boundaries.
- Negative controls for missing/duplicate roles, malformed output, provider outage, hostile markup, and boundary violations.
- Source records with stable IDs, HTTP(S) URL validation, optional retrieval timestamp and SHA-256 content digest.
- Explicit claim-to-source and conflicting-source references with duplicate/orphan rejection.
- Explicit per-agent claims, workflow evidence tags, stance values, and lifecycle traces.
- Mechanically defined observability metrics: disagreement, evidence coverage, unsupported claims, convergence complement, and observed role count.
- Orbit interpretation translating telemetry into Today / Patterns / Open Questions.
- JSON run artifacts preserving provider identity and non-empty source provenance.
- Frozen deterministic example with SHA-256 sidecar regenerated byte-for-byte in CI.
- Browser showcase UI with deterministic and hosted-provider selection. Hosted mode requires a server deployment; no model credential is accepted by browser code.
- GitHub Pages deployment workflow for the static deterministic showcase.
- Node built-in test suite and GitHub Actions CI.

## Run locally

The deterministic showcase requires no package dependencies:

```bash
python -m http.server 4173
```

Open `http://localhost:4173` and keep **Deterministic control** selected.

Run verification:

```bash
npm test
```

### Hosted model mode

Hosted mode requires a server environment capable of serving `api/run-agents.js` and a server-only OpenAI API key:

```bash
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.6-luna  # optional override
```

Never place the key in browser code or a public-prefixed environment variable. The current hosted endpoint performs model inference only; it does **not** perform external retrieval and instructs the model not to fabricate citations.

## Relationship to other projects

Orbit Driftwatch is an independent integration/showcase application. It adapts patterns from Orbit and Driftwatch, but cross-repository lineage does not transfer validation or evidence. DGAF, Tektite, MORSE, Amethyst, and Agent Control Plane remain separate projects with separate evidence boundaries.
